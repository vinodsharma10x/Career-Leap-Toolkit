# Resume Writing Best Practices

Reference guide for writing strong resume content. Use these guidelines when generating resume bullets and sections.

## Bullet Point Writing

### Strong Verb Starters
Vary these — don't start every bullet the same way.

**Building / Creating:**
Built, Developed, Designed, Created, Implemented, Architected, Engineered, Launched, Shipped, Prototyped

**Leading / Managing:**
Led, Managed, Directed, Coordinated, Oversaw, Mentored, Guided, Hired, Onboarded, Facilitated

**Improving / Optimizing:**
Improved, Optimized, Reduced, Increased, Streamlined, Automated, Refactored, Migrated, Modernized, Consolidated

**Analyzing / Strategizing:**
Analyzed, Researched, Evaluated, Identified, Defined, Prioritized, Mapped, Assessed, Discovered, Investigated

**Collaborating / Communicating:**
Collaborated, Partnered, Presented, Documented, Communicated, Advocated, Aligned, Influenced, Negotiated

### The Scope + Context + Outcome Formula

When numbers aren't available, use this pattern instead of inventing metrics:

**Pattern:** [Action verb] + [what you did] + [scope/context] + [outcome or why it mattered]

**Examples:**
- "Built real-time WebSocket notification system that replaced email-based alerts for the platform's 200+ enterprise clients"
- "Led migration from monolith to microservices, enabling independent deployments across 4 engineering teams"
- "Designed and implemented the onboarding flow that became the team's most-referenced pattern for new feature development"
- "Refactored the legacy payment processing module, reducing code complexity and eliminating the most common source of production incidents"

### When You DO Have Numbers

Use them naturally — don't force "increased X by Y%" into every bullet.

**Good uses of numbers:**
- Team size: "Led a team of 8 engineers"
- Scale: "Serving 50K daily active users"
- Impact: "Reduced page load time from 4.2s to 1.1s"
- Scope: "Across 3 product lines and 12 microservices"

**Bad uses (fluff):**
- "Improved efficiency by 200%" (unmeasurable)
- "Delivered 150% of quarterly targets" (vague)
- "Impacted millions of users" (too generic)

## Section-Specific Guidelines

### Professional Summary
- 2-3 sentences max
- Mention: years of experience, core expertise area, what you bring to the table
- Tailor to the target role
- Avoid: "results-driven professional", "passionate about", "seeking opportunities"
- Example: "Full-stack engineer with 6 years of experience building high-traffic web applications. Specialize in React and Node.js with a focus on performance optimization and developer experience. Looking for a senior role where I can lead a small team and own a product area."

### Work Experience
- Reverse chronological
- Most recent role: 4-6 bullets
- Previous roles: 2-4 bullets
- Roles older than 10 years: 1-2 bullets or just title/company/dates
- Each bullet should convey a different aspect of the role
- Mix technical achievements with leadership/collaboration bullets

### Skills Section
Categorize for scannability:

```
Languages: TypeScript, Python, Go, SQL
Frameworks: React, Next.js, Node.js, FastAPI
Cloud & DevOps: AWS (EC2, S3, Lambda), Docker, Kubernetes, Terraform
Databases: PostgreSQL, Redis, MongoDB, DynamoDB
Tools: Git, GitHub Actions, Datadog, Figma, Jira
```

- Only list skills you can speak to in an interview
- Order by relevance to target role
- Include tools and platforms, not just languages
- For PMs: include product tools (Amplitude, Mixpanel, Figma, Notion, Jira)

### Projects Section
Best for: early-career, career changers, open source contributors

```
### Project Name
Brief description of what it does and why. Mention key technical decisions.
Technologies: React, Node.js, PostgreSQL | github.com/user/project
```

### Education
- Degree, field, institution, graduation year
- GPA only if > 3.5 AND graduated within last 3 years
- Relevant coursework only for entry-level
- For bootcamps: list them but don't over-emphasize

## For Product Managers Specifically

PM resumes need different emphasis:

**Key bullet patterns:**
- "Defined product strategy for [area], resulting in [outcome]"
- "Owned the roadmap for [product/feature] serving [user segment]"
- "Conducted [type] research with [N] users to validate [hypothesis]"
- "Partnered with engineering and design to ship [feature] in [timeframe]"
- "Analyzed [data source] to identify [insight], leading to [decision]"

**PM-specific skills to highlight:**
- Product strategy & roadmapping
- User research & data analysis
- A/B testing & experimentation
- Stakeholder management
- Agile/Scrum methodology
- Specific analytics tools (Amplitude, Mixpanel, etc.)

## Formatting Rules

1. **Consistency is key** — same date format, same bullet style, same spacing throughout
2. **Dates:** "Jan 2020 – Present" or "2020 – Present" — pick one format and stick with it
3. **Location:** "San Francisco, CA" or "Remote" — keep it simple
4. **Company names:** Use official names, not abbreviations (unless universally known like "Google")
5. **Job titles:** Use your actual title, but you can clarify in parentheses if the title was unusual: "Software Craftsperson (Senior Engineer)"
